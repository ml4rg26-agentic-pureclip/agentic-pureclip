# Agent Module

This directory contains the core logic for the LangGraph-based agentic workflow. It acts as the brain of the project, orchestrating the Snakemake pipeline and LLM decision-making.

## Files

- **`graph.py`**: The main LangGraph state machine. Defines the nodes (`run_pipeline`, `run_scorers`, `agent_decide`, `finalize`) and edges that make up the optimization loop.
- **`state.py`**: Defines the `AgentState` schema using Python `TypedDict`. This state is passed between nodes and holds the history, current configuration, and best scores.
- **`logging_config.py`**: Setup for standardized logging across the agent module.

---

## Agent Optimization Workflow

The Agent operates as a state machine (built with LangGraph) that runs experiments, evaluates the results, and adjusts parameters. The core loop consists of three main steps:

1. **`run_pipeline`**: The Agent triggers the Snakemake pipeline using the current configuration (`run_config.yaml`). Snakemake executes `pureclip` (both on merged data and individual replicates) and `postprocess` to generate the binding regions and filtered binding sites.
2. **`run_scorers`**: The Agent executes `scorers/run_scorers.py`. This script calculates the quality metrics for the current run, including **`replicate_agreement`**, which measures the fraction of final binding sites that overlap with the `pureclip_regions.bed` found in **all** individual replicates.
3. **`agent_decide`**: A Large Language Model (Gemini) analyzes the `score_report.json` generated by the scorers, reviews the history of previous iterations, and proposes a new set of parameters for the next iteration to maximize the `objective_metric`.

This loop continues until the score stops improving or the maximum number of iterations is reached.

## Pipeline Parameters

The configuration file controls both the core peak-calling behavior of PureCLIP and the subsequent postprocessing logic. 

### 1. Actively Tuned by the Agent (Search Space)

The LLM is given specific bounds for these parameters and actively adjusts them during the optimization loop:

*   **`pureclip.bandwidth_nt`** (e.g., 20 - 100)
    *   **What it is**: The bandwidth for the Kernel Density Estimation (KDE) used internally by PureCLIP to smooth the read distribution.
    *   **How it affects the pipeline**: A *smaller* bandwidth makes PureCLIP sensitive to local spikes in reads (generating narrower peaks). A *larger* bandwidth smooths out the signal, which merges adjacent peaks and reduces background, but may blur closely spaced binding sites. This changes the raw crosslink sites output by the `pureclip` rule.

*   **`pureclip.merge_distance_nt`** (e.g., 4 - 16)
    *   **What it is**: The maximum nucleotide distance allowed between two adjacent crosslink sites to merge them into a single continuous "binding region".
    *   **How it affects the pipeline**: If set *higher*, sparse individual crosslink sites are clumped together into broad regions. If set *lower*, binding regions will be fragmented into multiple smaller regions. This defines the boundaries of `pureclip_regions.bed`.

*   **`postprocessing.min_crosslink_events`** (e.g., 2 - 6)
    *   **What it is**: The minimum number of individual crosslink sites (events) that must be present within a merged binding region for it to be kept.
    *   **How it affects the pipeline**: This is a direct stringency filter in `workflow/postprocess.py`. A *higher* value acts as a strict threshold, removing weak or spurious regions that only have 1 or 2 sites. This heavily dictates how many peaks make it into the final `binding_sites.reproducible.bed`.

### 2. Static Parameters (Not Tuned by Agent)

These parameters are defined in `run_config.yaml` but are kept constant during the Agent's search loop:

*   **`pureclip.use_input_covariate`** & **`pureclip.high_precision_mode`**
    *   **What it is**: Boolean flags to control whether PureCLIP incorporates the `input_control` BAM as a background covariate (`-ibam`), and whether to use high-precision mode (`-ld`).

*   **`postprocessing.min_region_length_nt`**
    *   **What it is**: Drops regions where the genomic distance between the start and end is too short.

*   **`postprocessing.force_width`** (e.g., 9)
    *   **What it is**: The final standardized width of the reproducible binding sites. 
    *   **How it affects the pipeline**: In `workflow/postprocess.py`, after filtering the regions, the script calculates the center (summit) of the region and expands it symmetrically to this fixed width. This ensures uniform peak widths for downstream motif analysis or scoring.

### The Feedback Loop

Because `replicate_agreement` is calculated by checking the overlap between the final `binding_sites.reproducible.bed` (influenced by `min_crosslink_events` and `force_width`) and the per-replicate `pureclip_regions.bed` (influenced by `bandwidth_nt` and `merge_distance_nt`), **every parameter the agent adjusts impacts the final score**. The LLM uses this feedback to balance sensitivity and specificity.
