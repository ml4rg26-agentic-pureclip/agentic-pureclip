\label{introduction}

% PLAIN-LANGUAGE GLOSSARY (comment only, not printed). Terms we must be able

%   RBP (RNA-binding protein): a protein that sticks to RNA and controls it
%       (e.g. which pieces get spliced, how long the RNA survives).
%   eCLIP: a lab method that finds WHERE on the RNA a given RBP binds. Its raw
%       output is short sequencing reads piled up along the genome.
%   Peak caller: software that turns that noisy pile-up of reads into a clean
%       list of real binding sites ("peaks").
%   PureCLIP: the specific peak caller we use.
%   Parameter: a numeric knob of PureCLIP (e.g. how much to smooth the signal).
%       Different knob settings => very different binding-site lists.
%   Motif: the short RNA "word" a protein prefers to bind (e.g. RBFOX2 likes
%       UGCAUG). Crisp = clear/short; degenerate = fuzzy; positional = defined
%       by location (e.g. next to a splice site) rather than by a fixed word.
%   Reproducibility: do the two lab repeats (replicates) agree on the sites?
%       Real sites recur in both; noise does not.
%   Splicing factor: an RBP whose job is RNA splicing; these often have fuzzy
%       or position-based motifs, so we use them as the "hard" test cases.
%   Cell line (K562, HepG2): two standard human cell types the data comes from.
% ─────────────────────────────────────────────────────────────────────────


\begin{itemize}
  \item RBPs drive post-transcriptional regulation; mapping their binding sites \emph{transcriptome-wide} is central to RNA biology. eCLIP yields per-nucleotide crosslink counts (aligned reads), not discrete sites, so a \emph{peak caller} is required as a post-processing step to turn this noisy read density into an interpretable binding-site set: its quality gates everything downstream.
  \item PureCLIP's (such a \textit{peak caller}) output is highly sensitive to a few numeric parameters, and there is no universal optimum. The best values depend on RBP, cell line and experiment quality including antibody efficiency.
  \item Manual tuning does not scale (hours per genome-wide run, subjective, dozens of ENCODE datasets), motivating an automated, reproducible framework.
  \item Contribution: an automated \emph{propose $\rightarrow$ run $\rightarrow$ score $\rightarrow$ iterate} framework with two interchangeable optimizers on identical evaluation infrastructure: An LLM agent (biological priors + reasoning) vs.\ Optuna/TPE (black-box Bayesian search).
  \item Scope: we test on \textbf{26 ENCODE datasets covering 15 proteins} from several RBP families and both cell lines (K562, HepG2), a deliberately diverse set chosen to check whether the method generalizes rather than overfitting a handful of proteins.
  % Detail (for us / supervisors, not for the printed bullet): the 26 datasets =
  % 5 original pilot datasets (proteins RBFOX2, QKI, PUM1) + 1 ENCORE RBFOX2 dataset
  % + 20 new datasets added in 2026-07 (12 new proteins). "15 proteins" counts each
  % protein once; some proteins appear in two cell lines (K562, HepG2), which is why
  % there are more datasets than proteins.
  \item Research question: does an automated LLM loop help us find good PureCLIP parameters, i.e.\ does it beat a standard automated search (Optuna) and the untuned defaults?
  \item Why binding-site quality matters: many of these proteins are splicing factors, which are clinically important because faulty RNA splicing drives many cancers and neurological diseases, so accurate binding-site maps for them are what make robust automated tuning worthwhile.
  % Status note (not printed): the LLM-vs-Optuna comparison on the 20 new datasets
  % is still running; the final head-to-head numbers are reported in Results.
\end{itemize}

\section{Theory}
\label{theory}

% ─────────────────────────────────────────────────────────────────────────
% PLAIN-LANGUAGE GLOSSARY for the technical terms in this section (comment
% only, not printed). Talking points for the supervisor meeting.
%   Crosslink: UV light "glues" the protein to the exact RNA spot it touches,
%       so sequencing can later read out that spot.
%   SMInput / input control: a background sample without the protein pulldown;
%       used to subtract non-specific signal (noise).
%   HMM (hidden Markov model): a statistical model that walks along the genome
%       and labels each position "bound" or "background"; PureCLIP uses one.
%   Bandwidth: how much PureCLIP smooths the signal. Merge distance: how close
%       two signals must be to count as one site. Both are tunable parameters.
%   PWM (position weight matrix): a table giving, per position, how much each
%       letter (A/C/G/U) is preferred. Used to score how well a site matches
%       the protein's motif. Log-odds = motif score vs. random-sequence score.
%   Shuffled background: randomly reordered sequence used as a "no real motif"
%       baseline, so we can tell true enrichment from chance.
%   Optuna / TPE (Tree-structured Parzen Estimator): a standard automated
%       search that tries parameter sets, learns from the scores, and proposes
%       the next set. No biology knowledge, purely data-driven. Our "baseline"
%       optimizer that the LLM is compared against.
% ─────────────────────────────────────────────────────────────────────────


\begin{itemize}
  \item eCLIP mechanism \parencite{vannostrand2016}: UV crosslink $\rightarrow$ immunoprecipitation $\rightarrow$ RT truncates at the crosslink $\rightarrow$ 5$'$ read end marks the contact at $\sim$nucleotide resolution. Two IP replicates + SMInput control.
  \item PureCLIP \parencite{krakau2017}: HMM over read 5$'$-start density; ``crosslinked'' vs.\ ``background'' states; optional SMInput covariate. Bandwidth = signal smoothing, merge distance = site grouping, wrong values give too few or too many sites.
  \item What makes a site set ``good'': reproducibility (chance-corrected), motif enrichment (PWM log-odds vs.\ shuffled background), benchmark recall (ENCODE reference regions).
  \item PWMs / position weight matrices: each candidate motif is scored as log-odds against a uniform background and scanned over a $\pm 15$\,nt window around every binding site (a site ``hits'' if it beats 80\% of the PWM's score range). Motifs are drawn from five databases (mCrossBase, ATtRACT, RBPmap, oRNAment, RBPDB). For each \emph{site set} (the binding sites produced by one run), we report the hit rate of the \emph{most enriched} motif, where enrichment is the hit rate over a per-window mononucleotide-shuffle background.
  \item LLM as a reasoning optimizer (domain priors + reading structured feedback) vs.\ Bayesian optimization / TPE \parencite{bergstra2011}, as implemented in Optuna \parencite{akiba2019} (surrogate model, exploration/exploitation, no domain knowledge).
  % Figure to add (not printed): pipeline schematic eCLIP reads -> PureCLIP ->
  % sites -> scoring.
\end{itemize}

\section{Architecture \& Implementation}
\label{method}


\begin{itemize}
  \item \textbf{Datasets \& registry.} 5 original + an ENCORE RBFOX2 dataset + 20 new (2026-07 ENCODE/Drive batches), \textbf{26 datasets across 15 RBPs} (12 newly added), in a table-driven registry (\texttt{pipeline/datasets.py}, \texttt{\_standard\_spec}); motifs auto-resolve per RBP/cell-line from a PWM catalog. All GRCh38, deduplicated; chr21 ``fast mode'' throughout ($\sim$minutes/trial vs.\ hours genome-wide).
  \item \textbf{Shared evaluation.} One \texttt{evaluate\_config()} entry point (Snakemake: merge IP $\rightarrow$ \texttt{pureclip} $\rightarrow$ per-replicate $\rightarrow$ post-process $\rightarrow$ score $\rightarrow$ \texttt{score\_report.json}), called identically by both optimizers so the comparison isolates \emph{proposal strategy}, not pipeline differences.
  \item \textbf{Tunable parameters (7).} PureCLIP: \texttt{bandwidth\_nt}[20--100],\\
  \texttt{merge\_distance\_nt}[4--16], \texttt{high\_precision\_mode}, \texttt{use\_input\_covariate}; post-processing: \texttt{min\_crosslink\_events}[2--6], \texttt{force\_width}[3--15],\\
  \texttt{cluster\_gap\_width}[4--16].
  \item \textbf{Composite objective (shared evaluation, not strategy).} $(0.5\cdot\text{repro} + 0.25\cdot\text{motif} + 0.25\cdot\text{recall}) \times \min(1, n_{\text{sites}}/10)$. The collapse guard was added after Optuna collapsed QKI to 1 ``perfect'' site for a fake composite of 0.78. \emph{Both} optimizers are scored by this identical objective, that is what makes the comparison apples-to-apples, but they use it differently: Optuna optimises the composite \emph{scalar} directly via TPE, whereas the LLM additionally sees the three \emph{decomposed} terms plus biological priors and per-iteration deltas and proposes one reasoned change. So the formula is the shared yardstick, and only the proposal strategy differs.
  \item \textbf{Motif-aware scoring.} Log-odds PWM hit-rate vs.\ shuffled background, reported for the most-enriched motif.
  \item \textbf{LLM optimizer.} DeepSeek \parencite{deepseek2024} (\texttt{deepseek-chat}, low temperature); each iteration receives biological priors (protein, motif, $\sim$9-nt footprint), bounds, current params, and a per-iteration score-delta table; proposes one change with reasoning; JSON validated against bounds with up to 3 retries.
  \item \textbf{Optuna optimizer.} TPESampler (seed 42), same \texttt{evaluate\_config}, larger trial budget for fairness.
  \item \textbf{Reproducible infrastructure (engineering contribution).} Manifest-driven batch runners (\texttt{batch\_runner.py}, \texttt{overnight\_batch.py}) and a live dashboard (Python JSON API + React SPA) that imports the \emph{same} \texttt{composite\_objective} so the UI never disagrees with the optimizer; per-dataset explorer, binding-site ``docking'' view, PDF export.
  \item \textbf{Reproducibility \& compute.} All runs are driven by versioned Snakemake configs; every trial appends to a per-run \texttt{decisions.jsonl} (params, scores, reasoning), so the whole search is auditable. Code + configs are released, and the full per-dataset ENCODE accession list is given in the Appendix.
  \item \textbf{Known method limitation.} No positional-motif prior is implemented: for the position-defined binders (U2AF1/2, SF3B1/4, RBM22) the auto-resolved target motif is only a weak proxy, so their motif term should be read with care (discussed in \S\ref{discussion}).

\end{itemize}

\section{Discussion, Limitations \& Future Work}
\label{discussion}


\begin{itemize}
  \item \textbf{Note: interpretations are expectations, not results yet.} The full LLM-vs-Optuna head-to-head (and the motif-difficulty side-experiment) are still running, so the points below are framed as what we expect the results to show, to be confirmed once the numbers land.
  \item \textbf{Interpretation via motif difficulty (hypothesis).} Proteins differ in how sequence-defined their binding is, a spectrum from \emph{crisp} k-mer motifs (RBFOX2 \texttt{UGCAUG}, PUM \texttt{UGUANAUA}), through \emph{degenerate} ones (HNRNPK C-rich, SRSF1 GA-rich), to \emph{positional} / non-k-mer binders (U2AF2 polypyrimidine tract, SF3B1/4 branch point). The motif term is a strong signal for the first group and a weak one for the last. We therefore expect the LLM's biological prior to help most where that signal is weakest and Optuna is searching blind, i.e.\ the LLM's margin over Optuna should widen crisp $\rightarrow$ degenerate $\rightarrow$ positional. A focused side-experiment (\texttt{config/insight\_llm\_vs\_optuna.yaml}: PUM2 / SRSF1 / HNRNPK / U2AF2 / SF3B4, K562, both optimizers) tests this; the batch is still running. Note the difficulty label is our manual annotation, not a quantity the pipeline computes, and if the margin does \emph{not} widen, that is itself a finding: the prior buys little on hard proteins.
  \item \textbf{The single fixed objective does not fit every dataset.} Our composite is one hard-coded formula applied to all datasets, which has two distinct consequences:
    \begin{itemize}
      \item \emph{Equal-replicate assumption (supervisor's point).} The reproducibility term (weight $0.5$) treats the two lab replicates as equally good. If we know one replicate is of much lower quality, its agreement score is misleading and the fixed weights cannot compensate. We keep the current weighting for time; quality-aware or learned weighting is the natural fix.
      \item \emph{Weak motif proxy for positional binders.} For U2AF/SF3B/RBM22 the motif term (weight $0.25$) is only a proxy, because binding is defined by splice-site position, not a k-mer. Composite scores for these should be read with care; a positional prior is the natural fix (identified, not implemented).
    \end{itemize}
  \item \textbf{Infrastructure as a contribution.} The shared-objective dashboard and manifest-driven runners make the study reproducible and the LLM-vs-Optuna comparison auditable per iteration.
  \item Limitations already outlined below: chr21-only, small search space, single LLM (no prompt ablation), budget asymmetry, mononucleotide-shuffle background, ENCODE reference is pipeline output not gold standard.
  \item \textbf{Future work.} The new data enables a paired cross-cell-line reproducibility analysis (K562 vs.\ HepG2), which we have not yet run. To pin down where any LLM advantage comes from, an iso-budget re-run (equal trial counts) and a prior-ablation of the LLM (removing the biological priors and the delta table) are the natural next steps.
\end{itemize}
