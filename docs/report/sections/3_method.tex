\section{Methods}
\label{method}

\subsection{Datasets and workflow}

The repository contains a table-driven registry of 26 ENCODE eCLIP
datasets~\parencite{encode2012,vannostrand2020} covering 15 RBPs in K562 and HepG2
cells. Each entry specifies two deduplicated IP BAM files, an SMInput BAM file, a
GRCh38 reference, benchmark regions, and RBP-specific motif information. The
completed head-to-head subset uses QKI, PUM1, PUM2, HNRNPK, SRSF1, U2AF2, and
SF3B4 in K562, and RBFOX2, HNRNPK, SRSF1, U2AF2, and SF3B4 in HepG2. These 12
pairs represent eight of the 15 registered RBPs. The prior ablation covers QKI,
PUM2, HNRNPK, SRSF1, U2AF2, and SF3B4 in K562. The same table-driven workflow can
run the remaining registered datasets, but they are outside the empirical subset
reported here. PureCLIP was restricted to chromosome~21 to make iterative
evaluation tractable. Reference regions were restricted to the same chromosome
before recall was calculated.

Both optimizers call the same \texttt{evaluate\_config()} entry point
(Figure~\ref{fig:pipeline}). The Snakemake workflow~\parencite{molder2021} merges
the IP replicates, runs PureCLIP\footnote{PureCLIP~2.0.4, the \texttt{pureclip2}
fork (\texttt{github.com/johan-stph/pureclip}).} on the merged BAM and separately
on each replicate, converts raw calls into standardized footprints, and calculates
the evaluation metrics. Each trial writes its parameters and scores to a
self-contained \texttt{score\_report.json} file.

\subsection{Composite objective}

For a call set with $n$ sites, the objective was
\begin{equation}
S = \left(0.50R_\mathrm{rep}+0.25R_\mathrm{motif}+0.25R_\mathrm{ref}\right)
\min\!\left(1,\frac{n}{10}\right),
\label{eq:composite}
\end{equation}
where $R_\mathrm{rep}$ is chance-corrected replicate agreement,
$R_\mathrm{motif}$ is the selected PWM hit rate, and $R_\mathrm{ref}$ is recall
of chromosome-21 reference regions. In practical terms, the components answer
three simple questions:

\begin{center}
\small
\begin{tabularx}{\linewidth}{@{}l>{\raggedright\arraybackslash}X@{}}
\toprule
Component & Intuitive calculation and interpretation \\
\midrule
Reproducibility & \textbf{Sites supported by both IP replicates $/$ all final
sites}, corrected for overlaps expected by chance. High values indicate that the
replicates independently support the same calls. \\
Motif support & \textbf{Sites containing the selected RBP motif $/$ all final
sites}. High values indicate that many calls match the protein's known sequence
preference. \\
Reference recall & \textbf{ENCODE reference regions overlapped $/$ all
chromosome-21 reference regions}. High values indicate that few known strong
regions were missed. \\
Yield guard & \textbf{Number of final sites $/$ 10}, capped at 1. This penalizes
only call sets with fewer than ten sites. \\
\bottomrule
\end{tabularx}
\end{center}

The component calculations were chosen to remain biologically interpretable.
Reproducibility is the fraction of final sites supported by both IP replicates,
adjusted for the overlap observed after chromosome-preserving genomic shuffling.
The adjustment follows the observed-versus-expected logic of Cohen's chance
correction~\parencite{cohen1960}; interval operations and shuffling use
BEDTools~\parencite{quinlan2010}.

Motif support is calculated in $\pm15$-nt site windows using standard PWM
log-odds scoring~\parencite{stormo1982}. All target-RBP PWMs available from the
five resources described in Section~\ref{theory} are considered. The pipeline
uses the hit rate of the PWM with the strongest enrichment over shuffled
sequences; the enrichment ratio is reported separately and is not itself part of
Equation~\ref{eq:composite}. Reference recall is the fraction of strong ENCODE
regions on chromosome~21 recovered by at least one final call
\parencite{vannostrand2020}.

All three components are bounded between zero and one. The weights and the
few-site penalty in Equation~\ref{eq:composite} are project-specific design
choices. If a component is unavailable, the implementation renormalizes the
remaining weights; all records analyzed here contained all three components.

\subsection{Experimental conditions}

The \emph{LLM-with-prior} arm used DeepSeek \texttt{deepseek-chat} at low
temperature\footnote{Sampling temperature $0.2$ via the DeepSeek API
(\texttt{api.deepseek.com/v1}).}
\parencite{deepseek2024} and received the RBP identity, known motifs, an expected
footprint, the parameter
bounds, the current configuration, and the decomposed score trajectory. The
prompt specified the objective components and the penalty applied to call sets
with fewer than ten sites. The model returned parameter changes as structured
JSON together with a natural-language rationale. During workflow development, a
second, more detailed prompt was tested on a small number of the same inputs. It
included additional guidance for interpreting the score components and a list of
putative target genes. This comparison was exploratory and was not included in
the optimizer evaluation; the compact prompt was retained for the reported
experiments. The
\emph{LLM-without-prior} arm received the same bounds, metrics, and trajectory,
but not the RBP identity or biological context. Thus, the ablation isolates the
information supplied in the biological prior; it does not remove numerical
feedback. Proposed JSON changes were validated against the search bounds and
retried after invalid responses. The \emph{TPE} arm used Optuna with seed 42 and
observed the scalar composite score.

All arms had a nominal cap of 16 evaluations and a stagnation threshold of 0.01
for four successive evaluations. For the LLM, counting began immediately. For
TPE, it began after the ten startup trials used by the sampler. Consequently,
the rule did not produce equal evaluation counts: LLM runs used five to nine
evaluations, whereas TPE runs used 14 to 16. LLM iteration~0 evaluated the shared
default configuration; TPE began with a sampled candidate. The reported
head-to-head cohort includes only dataset--cell-line pairs for which both arms
completed normally. All analyses are descriptive because each included arm was
run once and no estimate of between-run variability is available.
