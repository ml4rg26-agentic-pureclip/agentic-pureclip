The problem

Finding where proteins grab onto RNA

  • Proteins (RBPs) bind RNA to control it — splicing, stability, translation.
  • An experiment called eCLIP shows roughly where they bind, but only as a noisy pile-up of reads.
  • A tool called a peak caller (PureCLIP) turns that noise into a clean list of binding sites.
RNA + protein→ eCLIP reads
noisy pile-up→ PureCLIP
peak caller→ Binding sites
clean list

The peak caller is the step we need to get right.

Speaker 1 · ~1:00 — Keep it non-technical. Analogy: eCLIP is a blurry photo of where the protein sat; the peak caller sharpens it into "here are the actual spots." Everything downstream depends on this list being trustworthy.
Why it's hard

The tool has knobs, and the right setting keeps changing

  • PureCLIP has a handful of numeric settings (parameters). Small changes → wildly different site lists.
  • No universal best setting: it depends on the protein, the cell type, and experiment quality.
  • Manual tuning doesn't scale: one run takes hours, judging "good" is subjective, and there are dozens of datasets.
?

So: which parameters give trustworthy binding sites — automatically, and per dataset?

Speaker 1 · ~1:15 — Land the motivation clearly: this is a search problem no human wants to do by hand. End on the question on the right — that's what the whole project answers. Hand to Speaker 2.
Our approach

One loop, two interchangeable optimizers

Both optimizers call the exact same pipeline & scoring — so the comparison isolates only how they propose the next parameters.

Speaker 2 · ~0:50 — Walk the loop by the numbers: (1) optimizer proposes parameters → (2) identical pipeline runs and scores → (3) decide keep/stop → (4) feedback closes the loop. Stress: the ONLY difference between LLM and Optuna is step 4 (what they see) and how they propose. Everything grey/blue is shared.
Our approach

What we tune, and on what data

The knobs — 7 parameters

  • PureCLIP: how much to smooth the signal, and how far apart two peaks still count as one site.
  • Post-processing: how much evidence a site needs to be trusted, and how wide to make it.

Small changes here swing the number of called sites by orders of magnitude — that's why tuning matters.

The data

  • 26 ENCODE datasets, 15 proteins, across both cell lines (K562, HepG2).
  • Real experiments: two IP replicates + an input control each.
  • chr21 "fast mode" → each trial takes minutes, not hours, which is what makes an automated search loop feasible.

Same knobs, same data, same scoring for both optimizers — only how they choose the next setting differs.

Speaker 2 · ~0:50 — Make it concrete: 7 tunable knobs (describe in plain terms, don't read the parameter names), tested across 26 datasets / 15 proteins. chr21 fast mode is the practical trick that makes iterating feasible. Reinforce the fairness point, then lead into how we score.
How we judge "good"

One quality score, three biological signals

composite = 0.5 · reproducibility + 0.25 · motif + 0.25 · recall

Reproducibility

Do the two lab repeats agree on the sites? Real sites recur; noise doesn't.

Motif

Do sites contain the protein's preferred RNA "word"? A sign they're genuine.

Recall

Do we recover the known reference binding regions?

Collapse guard: the score is killed if the tool cheats by reporting only a few "perfect" sites.

Speaker 2 · ~0:50 — Both optimizers are judged by this same number. Reproducibility weighted highest = strongest evidence of real binding. Mention the collapse guard briefly: it stops a degenerate "1 perfect site" solution from winning. Hand to Speaker 3.

Discussion

An interesting idea we didn't get to test

While running the study, one question stood out that we set up but ran out of time to test — so we flag it as a promising follow-up, not a result:

Motif difficulty — how sequence-defined a protein's binding is: crisp a clear RNA word (RBFOX2 UGCAUG) · degenerate a fuzzy preference (HNRNPK C-rich) · positional defined by location (U2AF2, SF3B4 at splice sites). The motif signal gets weaker left → right.

The untested hypothesis: the LLM's biological prior might help most on the hard, weak-signal proteins, where a black-box search has little to go on. We prepared a focused experiment for this but couldn't run it in time.

What we can already say: unlike a black-box search, the LLM leaves a readable reasoning trail for each change — a real interpretability benefit, independent of the above.

Speaker 4 · ~0:55 — Be explicit: this is an idea we set up but did NOT test — present it as future work, not a finding. Explain motif difficulty simply, state the hypothesis, say we ran out of time. Then land the one thing we CAN claim: the LLM's reasoning trail (interpretability). The difficulty labels are our own annotation.
Limitations

What we'd caveat

Scoring is fixed

Equal weights, equal treatment of both lab repeats — a weaker replicate isn't down-weighted.

Weak signal for hard proteins

For positional binders the motif score is only a proxy — scores there need care.

Scope & budget

chr21 fast-mode only, single run per config, LLM and Optuna not yet equal-budget.

Speaker 4 · ~0:50 — Be upfront — supervisors flagged the fixed weights. Don't over-apologize; frame each as a known, bounded limitation with an obvious fix. Keep it to ~15s per box.
Conclusion

Takeaway & what's next

We built

  • An automated loop that tunes PureCLIP against a biological quality score.
  • A fair LLM-vs-standard-search comparison across 26 datasets, 15 proteins, easy → hard.

What's next

  • Finish the head-to-head on the hard proteins.
  • Equal-budget re-run & remove the LLM's priors to see what really drives its edge.
  • Genome-wide confirmation.

Bottom line: an LLM loop is a promising way to tune bioinformatics tools — likely most useful where the signal is weak and expert judgment matters.
