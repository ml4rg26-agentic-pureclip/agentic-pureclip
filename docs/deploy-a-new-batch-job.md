# Deploy a new batch job on the VM

Short runbook for deploying code and launching an `overnight_batch.py` job on
the de.NBI runner. The shared connection and deployment commands match the
[runner handover quick reference](../off/onboarding.md).

## Connect

```bash
ssh -p 30121 -i ~/.ssh/id_ed25519 ubuntu@194.94.4.28
cd /vol/storage1/johannes/projects/agentic-pureclip
```

The host is `agenticpureclipvm-751a3`. The project directory is a synchronized
copy, not a Git checkout. Its `.env`, `.venv`, `data/`, and `results/` already
exist and must not be overwritten by deployment.

## 1. Check the runner

```bash
cd /vol/storage1/johannes/projects/agentic-pureclip
df -h / /vol/storage1
du -sh data results
docker compose ps
tmux ls
ps -eo pid,etime,cmd | grep -E \
  'overnight_batch|agentic_pureclip.loop.(graph|optuna_runner)|pureclip2' | grep -v grep
```

Do not deploy while an optimization is running. Keep large data and results on
`/vol/storage1`; the root disk is small and nearly full.

## 2. Deploy the latest committed code

From the local repository, commit the intended changes and update `develop`:

```bash
git status --short
git pull --ff-only origin develop
```

Review the exact content delta without changing the runner:

```bash
git ls-files -z | rsync -rcni --from0 --files-from=- \
  --out-format='%i %n' \
  -e "ssh -p 30121 -i $HOME/.ssh/id_ed25519" ./ \
  ubuntu@194.94.4.28:/vol/storage1/johannes/projects/agentic-pureclip/
```

Deploy only Git-tracked files:

```bash
git ls-files -z | rsync -avrc --from0 --files-from=- \
  -e "ssh -p 30121 -i $HOME/.ssh/id_ed25519" ./ \
  ubuntu@194.94.4.28:/vol/storage1/johannes/projects/agentic-pureclip/
```

The `-c` option compares file contents, matching the dry run and ignoring
timestamp-only differences. Do not add `--delete` and do not use an unfiltered
working-directory sync. The tracked-file list preserves `.env`, `.venv`,
`data/`, `results/`, logs, and other runner-only state.

Update the existing environment, run the tests, and rebuild the dashboard:

```bash
ssh -p 30121 -i ~/.ssh/id_ed25519 ubuntu@194.94.4.28
cd /vol/storage1/johannes/projects/agentic-pureclip
~/.local/bin/uv sync --frozen
~/.local/bin/uv run pytest -q
docker compose up -d --build
docker compose ps
```

For a container restart without a code or image rebuild:

```bash
ssh -p 30121 -i ~/.ssh/id_ed25519 ubuntu@194.94.4.28
cd /vol/storage1/johannes/projects/agentic-pureclip
docker compose restart
docker compose ps
```

## 3. Archive previous results when required

This is optional and intentionally not part of every deployment. The batch
writes to `results/overnight/`; archive only after confirming that no job is
active:

```bash
cd /vol/storage1/johannes/projects/agentic-pureclip
ts=pre_final_$(date +%Y%m%d)
mkdir -p results/archive/$ts
mv results/overnight results/batch results/runs results/archive/$ts/ 2>/dev/null
```

## 4. Choose one launch mode

| | UI-generated CLI run | YAML-manifest batch |
|---|---|---|
| Scope | Exactly one dataset and one optimizer; may search several parameters | One or many jobs; each job chooses its dataset and optimizer |
| Configuration | Command-line flags generated by the dashboard Plan page | A version-controlled YAML file such as `config/smoke_final_jobs.yaml` |
| Execution | `agentic-pureclip-run` creates a one-job manifest and starts the Python runner detached | `scripts/run/overnight_batch.py` reads the supplied multi-job manifest and runs its jobs sequentially |
| Shell lifetime | No tmux required | Run inside tmux |
| Validation | Append `--dry-run` to the generated command | Invoke `overnight_batch.py --manifest ... --dry-run` |

Both modes use `scripts/run/overnight_batch.py` and write the same result format
under `results/overnight/`. Do not run the modes concurrently on this 32-core
runner; each documented job may use all 32 threads.

### A. Start one UI-generated run

The dashboard's Plan page only generates the command; it does **not** submit it.
One generated command always represents one dataset and one optimizer. Check
that no optimization is active, connect to the runner, change to the project
root, and execute the command there:

```bash
ssh -p 30121 -i ~/.ssh/id_ed25519 ubuntu@194.94.4.28
cd /vol/storage1/johannes/projects/agentic-pureclip
ps -eo pid,etime,cmd | grep -E \
  'overnight_batch|agentic_pureclip.loop.(graph|optuna_runner)|pureclip2' | grep -v grep

uv run agentic-pureclip-run \
  --dataset HNRNPK_K562 \
  --optimizer optuna \
  --max-iter 8 \
  --hours 4 \
  --threads 32 \
  --chr21 \
  --weight reproducibility=0.5 \
  --weight motif=0.25 \
  --weight recall=0.25 \
  --param pureclip.merge_distance_nt=4:16 \
  --param pureclip.bandwidth_nt=20:100 \
  --param pureclip.high_precision_mode=0:1 \
  --param pureclip.use_input_covariate=0:1 \
  --param postprocessing.min_crosslink_events=2:6 \
  --param postprocessing.force_width=3:15 \
  --param postprocessing.cluster_gap_width=4:16
```

Append `--dry-run` to inspect the generated manifest and launch command without
starting compute. Without `--dry-run`, the command starts immediately in a
detached process and prints:

- the timestamped job ID;
- the saved manifest at `config/ui_runs/<job_id>.yaml`;
- the log path `results/logs/ui_scheduled.log`.

No tmux session is required for a UI-generated CLI run; it survives closing the
SSH connection. Follow startup and execution with:

```bash
tail -f results/logs/ui_scheduled.log
```

Pressing `Ctrl-C` stops only `tail`, not the detached run. Per-job artifacts are
written under `results/overnight/<job_id>/`; aggregate status is written to
`results/overnight/summary.csv`, `jobs.jsonl`, and `iterations.jsonl` and is
shown in the dashboard.

The launcher does not queue behind another CLI-started run. If the process check
shows an active optimization, wait for it to finish before executing the new
command.

### B. Start a multi-job YAML-manifest batch

The Python file is the batch executor, not the job configuration. Define the
jobs in a YAML manifest. A manifest can contain multiple datasets, optimizers,
and experimental arms, for example:

```yaml
defaults:
  threads: 32
  learn_on_chr21: true
  per_job_timeout_min: 240
  objective_weights: {reproducibility: 0.5, motif: 0.25, recall: 0.25}

jobs:
  - {id: hnrnpk_optuna, dataset: HNRNPK_K562, optimizer: optuna, max_iter: 8}
  - {id: hnrnpk_llm, dataset: HNRNPK_K562, optimizer: llm, max_iter: 8}
  - {id: qki_optuna, dataset: QKI_K562, optimizer: optuna, max_iter: 8}
```

See [`config/smoke_final_jobs.yaml`](../config/smoke_final_jobs.yaml) for a small
multi-job example and
[`config/final_results_jobs.yaml`](../config/final_results_jobs.yaml) for a
larger batch.

Validate the manifest before launch:

```bash
cd /vol/storage1/johannes/projects/agentic-pureclip
~/.local/bin/uv run pytest -q
PYTHONPATH=. ~/.local/bin/uv run python scripts/run/overnight_batch.py \
  --manifest config/<manifest>.yaml --dry-run
```

Every intended job should report `data=OK`. Then launch the manifest in tmux:

```bash
cd /vol/storage1/johannes/projects/agentic-pureclip
tmux new -s batch
export PATH=/vol/storage1/johannes/projects:$HOME/.local/bin:$PATH
PYTHONPATH=. ~/.local/bin/uv run python scripts/run/overnight_batch.py \
  --manifest config/<manifest>.yaml --hours <N> --no-repeat \
  --pureclip-dir /vol/storage1/johannes/projects
```

Detach with `Ctrl-b d`; reattach with `tmux attach -t batch`.

Available manifests include `config/smoke_final_jobs.yaml` for a small pipeline
check and `config/final_results_jobs.yaml` for the full batch. Confirm current
job counts and expected runtime from the manifest rather than relying on an old
estimate in this runbook.

## 5. Monitor either launch mode

- `results/overnight/summary.csv` — one row per job.
- `results/overnight/jobs.jsonl` and `iterations.jsonl` — aggregate records.
- `results/overnight/<job_id>/run.log` and `decisions.jsonl` — per-job details.

The dashboard is read-only monitoring. Open it through the same full SSH
endpoint:

```bash
ssh -N -L 8080:localhost:8080 -p 30121 \
  -i ~/.ssh/id_ed25519 ubuntu@194.94.4.28
```

Then visit `http://localhost:8080`.
